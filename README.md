### 3. Предсказание результатов вычислений

* **Выражение:** `2 + 3 * 4`
  * **Прогноз:** `14`
  * **Результат Python:** `14`
  * **Объяснение:** Сначала выполняется умножение, затем сложение.

* **Выражение:** `(2 + 3) * 4`
  * **Прогноз:** `20`
  * **Результат Python:** `20`
  * **Объяснение:** Скобки меняют приоритет, поэтому сначала выполняется сложение.

* **Выражение:** `17 // 5`
  * **Прогноз:** `3`
  * **Результат Python:** `3`
  * **Объяснение:** Целочисленное деление оставляет только целую часть числа.

* **Выражение:** `17 % 5`
  * **Прогноз:** `2`
  * **Результат Python:** `2`
  * **Объяснение:** Остаток от деления (17 минус 15).

* **Выражение:** `-7 // 2`
  * **Прогноз:** `-4`
  * **Результат Python:** `-4`
  * **Объяснение:** Целочисленное деление в Python всегда округляется в меньшую сторону (к минус бесконечности). Поэтому результат `-3.5` превращается в `-4`. Различий с прогнозом нет, так как это стандартное поведение языка.

### 5. Ответы на теоретические вопросы

* **Отличие `/` от `//`:**
  * Оператор `/` — это обычное деление, которое всегда возвращает дробное число (`float`), даже если делится нацело (например, `4 / 2` будет `2.0`).
  * Оператор `//` — это целочисленное деление, которое отбрасывает дробную часть и возвращает только целое число, округляя результат в меньшую сторону.

* **Смысл остатка (`%`):**
  * Оператор `%` находит то, что осталось после деления одного целого числа на другое. Например, `17 % 5` даст `2`, так как в 17 число 5 помещается ровно 3 раза (это 15), а 2 остается.

* **Почему форматирование не устраняет неточность `float`:**
  * Форматирование (например, вывод `.2f`) просто визуально округляет и красиво обрезает цифры при выводе на экран. Внутри памяти компьютера число все равно хранится в двоичном виде с микроскопической погрешностью (из-за невозможности точно представить некоторые десятичные дроби вроде `0.1` или `0.2` в двоичной системе). Округление при выводе маскирует неточность для пользователя, но не исправляет её в самих вычислениях.
